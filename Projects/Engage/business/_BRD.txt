Each task follows a defined lifecycle starting from task creation and assignment, progressing through status changes, and concluding when the task is completed or cancelled.To maintain transparency and accountability, every action taken on a task requires a mandatory comment and is recorded within the task history log. The system enforces comment validation rules, prevents actions without proper documentation, and maintains a complete audit trail of all changes.The module also incorporates Service Level Agreement (SLA) monitoring based on task priority levels. SLA timers begin when the task is created and are calculated within defined business hours. The system monitors SLA progress, generates notifications when tasks approach their SLA threshold, and marks tasks as overdue when the SLA expires. Notifications and visual indicators ensure that administrators, managers, and assigned users are aware of tasks that require attention.Critical tasks receive immediate notification upon creation due to their high priority and shorter SLA duration. The system also supports escalation and reassignment workflows to ensure that tasks can be redirected when required.Additionally, administrative configuration options allow SLA durations to be defined and managed through the business configuration settings. All SLA configuration changes are recorded for audit purposes.This functionality ensures improved operational control, visibility across teams, and adherence to defined service timelines.Business ObjectivesThe objectives of implementing the Task Management and SLA Workflow module are:Ensure that every task action performed within the system is documented through mandatory comments for operational visibility and accountability.Provide a structured workflow that enables users to update task status through predefined actions including reassignment, escalation, reprioritisation, and completion.Enable administrators and managers to track task progress through clearly defined statuses and historical activity logs.Introduce SLA monitoring to ensure tasks are addressed within defined timeframes based on priority levels.Notify relevant users when tasks approach SLA thresholds to prevent overdue tasks.Highlight overdue tasks visually within the system to improve response time and operational awareness.Enable escalation and reassignment capabilities to ensure tasks can be redirected to the appropriate users when necessary.Maintain a complete audit trail of all task actions including user activity, timestamps, and comments.Allow SLA configurations to be managed by administrators through configurable business settings.Ensure critical tasks receive immediate attention through system-generated notifications.BackgroundDuring operational workflows, tasks are created and assigned to users within the organization. These tasks require a structured approach for monitoring progress, ensuring timely resolution, and maintaining visibility across administrative and managerial roles.The absence of consistent documentation and standardized task handling processes can lead to delays, lack of accountability, and reduced operational transparency. To address these challenges, the Task Management and SLA Workflow module introduces structured processes that govern how tasks are handled within the system.The system ensures that every action taken on a task is recorded with a mandatory comment. This requirement ensures that stakeholders have visibility into the actions performed and the reasoning behind them. A comment reminder banner is displayed within the interface to reinforce this requirement.The module introduces predefined task statuses that guide the lifecycle of a task. Users interact with tasks through a status action dropdown that allows them to update the task status while recording supporting comments.In addition to status tracking, the module introduces SLA monitoring based on task priority. Each task is assigned a priority level that determines the allowed timeframe for completion. The SLA timer begins when the task is created and continues running regardless of status changes such as reassignment or escalation.To ensure that tasks receive attention before becoming overdue, the system monitors SLA thresholds and notifies relevant users when a task approaches its deadline. If the SLA expires without completion, the system marks the task as overdue and visually highlights it within the user interface.Critical priority tasks require faster response times and therefore trigger immediate notifications upon creation.The system also supports escalation and reassignment workflows, enabling tasks to be transferred to other users when required. All such actions are recorded in the task history log, ensuring complete traceability.Through these mechanisms, the Task Management and SLA Workflow module ensures consistent task handling, improved visibility, and adherence to operational timelines.ScopeIn ScopeThe following functionalities are included within the Task Management and SLA Workflow module:Task Status ManagementThe system shall provide a dropdown menu that allows users to perform task status actions. The available options include:Action CompletedIn ProgressReassignedReprioritisedCancelled (Action no longer required)EscalationThe selected option will update the stored status of the task.Task Status LifecycleThe system shall support the following task statuses:AssignedIn ProgressReassignedReprioritisedEscalatedCancelledCompletedOverdueWhen a task is created, its default status shall be Assigned.Mandatory Comment RequirementBefore performing any task action, users must enter a comment explaining the action taken.The system shall not allow any action to be performed without entering a valid comment.The action button shall remain disabled until a valid comment is entered.Comment ReminderThe system shall display a reminder banner above the comment box.The banner will remind users that comments are required for every action taken for visibility.Task ReassignmentWhen the Reassigned action is selected:The user shall be able to choose another user.The selected user must belong to the same Business Area as the task.The Business Area shall be derived from the user profile.Ownership of the task shall transfer to the newly selected user.The SLA timer shall continue running and shall not reset.The previous owner shall only be able to view the task within the task history and not within their active task list.Task EscalationWhen the Escalation action is selected:The user shall be able to choose any user.Ownership of the task shall transfer to the selected user.The SLA timer shall continue running and shall not reset.The escalation action shall be recorded within the task history log.Task ReprioritisationWhen the Reprioritise action is selected:The user shall be able to change the task priority.The priority can be changed to any available level.When the priority changes:The SLA shall be recalculated.The SLA timer shall reset based on the new priority.Task CompletionWhen Action Completed is selected:The task shall move to the Completed tab.Task CancellationWhen Cancelled (Action no longer required) is selected:The task shall move to the Completed tab.The task status shall remain Cancelled.Task Editing RestrictionsAfter a task is created:No task data fields shall be editable.Any changes to a task must occur through status actions such as:ReassignmentEscalationReprioritisationStatus updatesEach action must include a new comment and must be stored within the task history.StakeholdersNameRoleResponsibilityAdminSystem
