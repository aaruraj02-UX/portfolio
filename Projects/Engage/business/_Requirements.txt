Task Module – Combined Requirements (MOM + Interview Summary)Prepared for: Engage / Field & Web TeamsPrepared by: Arumugam V – Principal UX Engineer ILast updated: 25 Feb 20261. OverviewThis document consolidates all Task Module requirements derived from the uploaded Minutes of Meeting (MOM) and the Interview Summary. It focuses on end-to-end task lifecycle, roles and permissions, dashboard behaviors, SLA/escalation logic, interaction patterns, and audit/compliance needs.2. Objectives & ScopeObjectives Provide a clear, efficient workflow for creating, viewing, acting on, and closing operational tasks. Ensure tasks influence utilisation and SLA tracking where appropriate. Support managerial oversight, auditability, and process improvement via structured reasons and analytics.In Scope Web task dashboard and detail views Task lifecycle & statuses, actions, and audit trail SLA definitions, escalation rules, and metrics Search/filtering, manager/admin views, and reporting3. User RolesPrimary roles: Agent/Assignee – works tasks, updates status, adds comments/evidence. Manager – monitors SLA, reallocates work, views area-wide tasks. Admin – global visibility across business areas with configuration access (SLA values, rules).4. Task Lifecycle & StatusesStatuses supported: New, In Progress, Reassigned, Reprioritized, Escalated, Cancelled, Completed. Active screens show only open tasks; completed and outcome states are moved to the Completed section for audit. When a user opens a task, status cannot remain New—an explicit status update is required before exiting.5. Core Actions & RulesComplete: Marks task done and removes it from active list; appears under Completed for audit.Reject: Requires a structured reason via guided questions; used when task is invalid or not actionable. Adds to analytics on rejection causes.Reassign: Delegation via reassignment with mandatory comment; ownership remains traceable through audit trail. Separate “Create Action” is not needed as reassignment covers delegation.Mark In Progress: Used when immediate resolution is not possible; SLA timer continues. Mandatory comment required; overdue in-progress tasks should be visibly highlighted.6. Escalation & SLA Behaviour Hierarchical escalation when tasks remain unresolved beyond configured duration; uses organisational reporting lines. SLA categories: Within SLA, Approaching SLA (near threshold), Past SLA (breached). Thresholds are configurable by priority (e.g., last 30 min of a 4-hour SLA = Approaching). Changes to SLA values require confirmation and are fully audited (who/what/when/why).7. Dashboard, Metrics & Views Dashboard metrics: Total tasks, Inside SLA, Approaching SLA, Past SLA; similar to Jobs at Risk behaviour. Manager view: see all outstanding tasks, SLA proximity, workload across business area(s). Admin view: holistic visibility across all business areas with filters (e.g., Metering, Motor, Field).8. Interaction Design & Layout Default to list/linear layout with initial collapsed task cards; expand to reveal full actions. Grid views can confuse reading order for operational usage. Provide clear Complete / Reject CTA grouping. Add optional Snooze/Dismiss with reason if required by operations (non-blocking).9. Search & Filtering Search by Agent name, Task name, Task type, Status, Assigned personnel, Overdue flag. Provide quick filters consistent with existing web application behaviour for parity.10. Task Creation (Web Users)Managers/Web users can manually create tasks with comments and assignment. These ad-hoc tasks may not include deep system links and primarily act as operational instructions.11. Ownership, Audit Trail & Compliance Every state change/comment/reassignment is recorded with user, timestamp, and reason where applicable. Maintain visibility of lifecycle history to ensure accountability even when tasks are reassigned.12. Field App Integration (Lightweight Option)Feasibility to notify field users and allow simple completion acknowledgement without a full mobile task module to be explored; timeline impact to be validated.13. Completed Section Metrics & AnalyticsCompleted view retains outcomes (Completed, Reassigned, Reprioritized, Escalated, Cancelled) for future trend analysis and delegation effectiveness reporting. In-Progress contributes to dashboard metrics but remains active until resolved.14. Non-Functional & UI Considerations Apply Engage theme with darker neutrals to improve scannability without overpowering UI. Accessibility: clear status colours with sufficient contrast; keyboard navigation for search and filtering.15. Open Items & Dependencies Confirm escalation hierarchy source-of-truth and mapping to user directory. Finalise SLA thresholds per priority and business area. Validate feasibility and scope of field app notifications for task actions.Appendix A – Source Mapping MOM.doc – Sections on Task Dashboard, Statuses, SLA, Escalation, Manager/Admin views, Search/Filter, Creation, Auditability, Field App integration. Interview Summary.doc – Items on lifecycle (Complete/Reject), rejection reasons/scenarios, grid vs linear layout guidance, and overdue behaviour.
